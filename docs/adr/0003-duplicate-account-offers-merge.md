# A device match during registration offers a merge choice, not a hard block

Today, `existsDeviceId` finding a match during `registUser` throws `DeviceAlreadyRegisteredException` and unconditionally blocks registration — the only device-reuse policy that existed before multi-provider login. Once a Linked Identity (LINE/Apple/Google/phone) is already recognized, `existsDeviceId` is skipped entirely and the call is treated as a login — multi-device access to one Account is the point. The open question was what should happen when neither is true: a *new* external identity, on a device that already has an *existing* Account.

We decided that case should offer the user a choice — link the new identity to the existing device-matched Account, or knowingly create a separate one — rather than silently hard-blocking (today's behavior, which would now incorrectly stop a legitimate second Account holder sharing a device) or silently creating a duplicate (which would strand the user's history under an Account they didn't mean to abandon). We explicitly did not build automatic cross-provider account matching (e.g. by email) to detect this case more proactively — with few real users so far, that's more investment than the problem currently warrants; the device signal alone is enough to prompt, not to decide. Exact UX/endpoint mechanics are left to a later ticket ("登録/ログインUXフロー設計").
