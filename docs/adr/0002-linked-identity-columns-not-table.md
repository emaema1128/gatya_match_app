# Linked identities are columns on `user`, not a separate table

bloom already stores a LINE identity as `user.line_user_id`, set via `User::setLineUserId()`. When scoping Apple/Google/phone-number login (the auth-method-redesign map), we considered introducing a normalized `external_identity(system_id, provider, provider_user_id)` table instead — cleaner for adding future providers without a schema change, and avoids the LINE precedent's own quirk where the actual web-login lookup goes through `line_account_user_info` (a LINE Official Account bookkeeping table) rather than `user.line_user_id` directly.

We chose to follow the existing column-per-provider precedent instead: new nullable, uniquely-indexed `apple_user_id`, `google_sub`, and a verified phone number column, mirroring `line_user_id`. Consistency with bloom's existing pattern won out over normalization for a four-provider set that isn't expected to grow often. As a consequence, the new *mobile* LINE login path looks up/writes `user.line_user_id` directly rather than reusing `line_account_user_info` — the existing *web* LINE login flow is untouched and keeps using its own lookup; the two are accepted to diverge rather than be unified, since the web flow is outside this Flutter-focused project's scope.
